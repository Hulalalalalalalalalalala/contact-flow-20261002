# 客户跟进工作台

按规范化邮箱登记联系人，记录跟进，并按组织检索联系人及按日期查看跟进。

## 运行

需要 Python 3.10 或更新版本，仅使用标准库，无依赖安装步骤。请在本目录运行：

```sh
python3 -m contact_flow --root ./state demo
python3 -m unittest discover -s tests -v
```

这是本地命令行程序，不监听网络端口，无账户或密码。`demo` 在指定 root 的临时子目录中读取 examples 样例并演示业务，结束后清理样例状态，不改变现有数据。

## 正常使用

公开 API：`from contact_flow import ContactFlow`，然后 `ContactFlow(root)`。每个命令接收可选的 JSON 文件，其对象键与 API 方法参数一致。例如：

```sh
python3 -m contact_flow --root ./state add examples/contacts.json
```

JSON 数组会按顺序执行多个独立操作；先前成功操作保留，后续失败不会回滚整批。重跑登记命令遇到已存在的标识会报错。

- `add` → `ContactFlow.add_contact(...)`。参数名见 `core.py` 的公开方法签名。
- `update-contact` → `ContactFlow.update_contact(contact_id, changes)`。局部更新已登记联系人的资料：`changes` 是非空对象，仅允许 `name`、`email`、`organization` 中的一个或多个键，未提供的字段保留原值；成功返回与 `add` 相同结构的完整联系人对象，`contact_id` 保持不变。`contact_id` 去除首尾空白后须非空且区分大小写，标识非法或联系人不存在抛 `ValueError`。`changes` 不是对象、为空、含不允许的键，或字段值不是字符串、去首尾空白后为空，均抛 `ValueError`；`None` 不能用于清空字段。姓名与组织只去除首尾空白并保留内部空白；邮箱去除首尾空白后转小写，须恰有一个 `@`、两侧非空且不含任何空白，否则抛 `ValueError`。规范化后的邮箱与其他联系人重复时抛 `ValueError`，与自身当前邮箱相同则允许。一次调用中的所有字段共同成功或共同失败，任何拒绝都保留原数据文件字节；数据目录原本不存在时不创建目录或文件。所有字段规范化后均与当前值相同时返回当前联系人且不改写文件。组织修改立即反映在 `find` 的组织筛选和 `funnel-report` 的组织分组及 CSV 中（该联系人及其全部机会按新组织计入，未筛选的联系人总数、机会总数及各阶段总数不变）；标签、跟进记录、机会归属与阶段、提醒日期与备注均保留，旧数据缺少这些可选集合时也能更新。邮箱修改后旧邮箱可重新登记，新邮箱受既有登记与导入去重规则约束。
- `update-contacts` → `ContactFlow.update_contacts(updates)`。一次提交整批资料更新，批内所有更新共同成功或共同失败（原子）。`updates` 只接受列表，空列表返回空数组且不写入、不创建数据目录；每项是恰含 `contact_id` 与 `changes` 的对象，`changes` 规则与 `update-contact` 完全一致（非空对象，仅允许 `name`、`email`、`organization`，未提供字段保留原值，字段值与邮箱格式的校验、规范化相同）。元素不是对象、缺少或多出键、`changes` 不是非空对象或含其他字段、字段值非法，均抛 `ValueError`。标识去首尾空白后须非空且区分大小写；标识非法、联系人未知，或规范化后的标识在批内重复（即使两项完全相同）均抛 `ValueError`。邮箱唯一性按整批更新后的全部联系人判断（包含未参与更新的联系人）：批内互换或循环交换邮箱允许成功，参与者单独占用未参与者的邮箱或更新后仍存在任何重复则整批抛 `ValueError`。成功返回按输入顺序排列的完整联系人数组，结构与 `add` 一致，`contact_id` 不变，重新打开同一 root 后可查到结果。任何校验失败都不保留部分修改，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建；整批结果规范化后均与原值相同时返回完整数组而不改写文件。更新同样保留标签、跟进记录、机会归属及阶段、提醒日期和备注，旧数据缺少可选集合时也能更新；组织变化立即反映在 `find` 的组织筛选和 `funnel-report` 的漏斗分组中，未筛选的联系人及机会各阶段总数不变。命令通过含 `updates` 的 JSON 对象提交一批；缺少必填参数抛 `TypeError`（经标准错误信封返回 2）。外层 JSON 数组仍是对整批方法的逐项独立调用，先前成功的批次保留。
- `rename-contacts` → `ContactFlow.rename_contacts(renames)`。一次提交整批联系人标识更正，在保留每位联系人资料与关联内容的前提下调整标识，批内所有更正共同成功或共同失败（原子）。`renames` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `old_id` 与 `new_id` 的对象：元素不是对象、缺键或多键均抛 `ValueError`。两个标识去除首尾空白后须为非空字符串且区分大小写；标识非法、旧标识未知、规范化后的旧标识或新标识在批内重复（即使两项完全相同），或新标识被未参与本批更正的联系人占用，均抛 `ValueError`，所有联系人按调用前身份检查。整批按调用前的联系人身份同时更名：允许原样更名、互换与循环交换（A→B、B→C 表示原 A 改为 B、原 B 改为 C），调整输入顺序只改变返回顺序，不改变最终数据。成功返回按输入顺序排列的完整联系人数组，结构与 `add` 一致，仅 `contact_id` 改为新标识，姓名、邮箱与组织不变；整批均为原样更名时返回结果而不改写文件。标签、跟进、提醒与所有阶段的机会随各自联系人更名：跟进日期、备注、重复条数及保存顺序保留；提醒到期日、备注与已有周期字段保留；机会标识、标题、阶段、金额与阶段历史不变，未设置金额时不补金额字段。无关联系人及其关联数据保留原值；旧数据缺少可选集合时按空集合处理。任何校验失败都不保留部分修改，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。重新打开同一 root 后结果仍有效，查询显示新标识，报表沿用既有筛选、排序与 CSV 格式，人数、机会各阶段数量与金额、跟进条数不变；未被复用的旧标识按未知联系人处理，可重新登记。既有登记去重、资料更新、合并及其他公开入口保留原行为，资料更新仍不接受修改 `contact_id`。命令通过含 `renames` 的 JSON 对象提交一批，成功输出 JSON 并退出 0，失败向标准错误输出含 `error` 的 JSON 并退出 2；外层 JSON 数组仍是对整批方法的逐项独立调用，后项失败保留前项结果。
- `follow-up` → `ContactFlow.follow_up(...)`。参数名见 `core.py` 的公开方法签名。
- `find` → `ContactFlow.find(...)`。参数名见 `core.py` 的公开方法签名。
- `timeline` → `ContactFlow.timeline(...)`。参数名见 `core.py` 的公开方法签名。
- `merge` → `ContactFlow.merge_contacts(...)`。把源联系人合入目标联系人：删除源联系人，其全部跟进记录归入目标，返回目标联系人和转移数量。参数名见 `core.py` 的公开方法签名。
- `merge-batch` → `ContactFlow.batch_merge_contacts(merges)`。一次提交整批合并关系，批内所有合并共同成功或共同失败（原子），单条 `merge` 入口行为不变。`merges` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `source_id` 与 `target_id` 的对象：元素不是对象、缺键或多键均抛 `ValueError`。两个标识去除首尾空白后须为非空字符串且区分大小写；标识非法、联系人未知、源与目标相同、规范化后的源标识在批内重复（即使两项完全相同），或合并关系形成任意环（如 A→B 且 B→A）均抛 `ValueError`，所有联系人按调用前状态检查。同一源只能出现一次；多个源可指向同一目标，目标也可在本批中作为源，链式关系统一合入不再作为源的最终目标（如 A→B、B→C 后仅保留 C）；交换项目顺序只改变返回顺序，不改变保存结果。成功返回按输入顺序排列的数组，每项仅含 `source_id`、`contact`、`moved_followups`：分别为规范化后的源标识、最终目标的完整联系人资料，以及调用前直属该源的跟进条数（链上其他源的记录不重复计数）。最终目标的姓名、邮箱和组织保留，所有源联系人删除；标签取整组（最终目标与全部源）去重并集并沿用既有排序；跟进仅改归属，保存顺序与重复记录保留；全部机会（含 `won`/`lost` 终态）改归最终目标，标识、标题、阶段、金额和阶段历史不变；每组提醒取最早到期的一条，同日优先最终目标原提醒，否则取原归属标识按 Unicode 码点最小者，选中提醒除归属外保留全部字段，组内无提醒则仍为空。无关联系人及其关联数据保留原值。任何校验失败都不保留部分修改，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建；旧数据缺少跟进、机会、标签或提醒集合时按空集合处理。重新打开同一 root 后，查询及报表按最终归属和标签反映结果，未筛选的机会各阶段数量、金额总计和跟进条数不变。命令通过含 `merges` 的 JSON 对象提交一批，成功输出 JSON 并退出 0，失败向标准错误输出含 `error` 的 JSON 对象并退出 2；外层 JSON 数组仍是对整批方法的逐项独立调用，后批失败保留先前成功批次。
- `set-tags` → `ContactFlow.set_tags(contact_id, tags)`。整组替换联系人标签，返回规范化后的标签数组；传空数组清除标签。标签须为字符串列表，每项去除首尾空白后非空，并按 casefold 规范化、去重，返回按 Unicode 码点排序。
- `get-tags` → `ContactFlow.get_tags(contact_id)`。返回联系人的标签数组；新联系人或旧数据默认返回空数组。
- `import-contacts` → `ContactFlow.import_contacts(csv_path)`。一次性整体导入本地 CSV：参数 JSON 形如 `{"csv_path": "people.csv"}`，相对路径按当前工作目录解释。文件须为 UTF-8（可带 BOM），表头只能是 `contact_id,name,email,organization` 四列、名称精确匹配、顺序任意；缺失、重复或额外列一律拒绝。支持标准引号、字段内逗号与换行；零字段空行忽略，其余字段数不符、CSV 语法错误或编码非法一律拒绝。整份文件先全部校验：规范化后的标识或邮箱与已有联系人或批内其他记录重复（即使两行完全相同）时整批拒绝，不覆盖、不跳过、不部分写入。成功返回按文件记录顺序排列的联系人数组，内容与 `add` 返回一致；空文件或无表头一律拒绝，只有合法表头（或其后仅有空行）时返回空数组且不创建数据目录。源文件不存在报 `FileNotFoundError`、无权限报 `PermissionError`、`csv_path` 类型非法或为空白字符串报 `ValueError`。
- `import-followups` → `ContactFlow.import_followups(csv_path)`。面向**已存在联系人**一次性整体批量导入跟进记录，不创建联系人。参数 JSON 形如 `{"csv_path": "followups.csv"}`，相对路径按当前工作目录解释。文件须为 UTF-8（可带 BOM），表头只能是 `contact_id,on,note` 三列、名称精确匹配、顺序任意；缺失、重复或额外列一律拒绝。支持标准引号、字段内逗号与换行；只忽略零字段空行，其余记录列数不符、CSV 语法错误或编码非法一律抛 `ValueError`。`contact_id` 去除首尾空白后须非空且区分大小写；`on` 去除首尾空白后须为真实 `YYYY-MM-DD` 日期（允许过去、未来日期与合法闰日，不读取系统日期）；`note` 去除首尾空白后须非空，保留内部空白与换行。任一字段非法或联系人未知都整批拒绝（不跳过、不部分写入），并保留原数据文件字节，数据目录原本不存在时不创建目录或文件。成功时按文件记录顺序追加，返回同顺序的跟进数组，每项仅含 `contact_id`、`on`、`note` 且值为规范化结果；原有跟进不改动，批内或与已有数据相同的记录逐条保留，重复导入同一文件也会再次追加。空文件或无表头抛 `ValueError`；合法表头后没有记录（或仅有空行）时返回空数组且不写入。重新打开同一 root 后，新记录可在 `timeline` 与 `followup-report` 中查询：沿用既有日期排序，同日同一联系人先保留原记录顺序，再排列本批记录。导入不改变联系人资料、标签、机会、提醒和漏斗统计。源文件不存在报 `FileNotFoundError`、无权限报 `PermissionError`、`csv_path` 类型非法或为空白字符串报 `ValueError`。旧数据缺少跟进集合时按空集合处理。
- `import-opportunities` → `ContactFlow.import_opportunities(csv_path)`。面向**已存在联系人**一次性整体批量导入销售机会，不创建联系人。参数 JSON 形如 `{"csv_path": "opportunities.csv"}`，相对路径按当前工作目录解释。文件须为 UTF-8（可带 BOM），表头只能是 `opportunity_id,contact_id,title,stage` 四列、名称精确匹配、顺序任意；缺失、重复或额外列一律拒绝。支持标准引号、字段内逗号与换行；只忽略零字段空行，其余记录列数不符、CSV 语法错误或编码非法一律抛 `ValueError`。四个字段去除首尾空白后均须非空：两个标识区分大小写（`O1` 与 `o1` 不同），联系人标识与机会标识互不占用；标题保留内部空白与换行；`stage` 只接受 `new`、`qualified`、`won`、`lost`，大小写不转换，导入时直接保留所填历史阶段，不做阶段转移校验、不反推历史阶段。整份文件共同成功或共同失败：每条机会只能归属已存在联系人，同一联系人可导入多个机会；规范化后的机会标识与已有机会或批内其他记录重复（即使两行内容完全相同）时整批拒绝，不覆盖、不跳过、不部分写入。未知联系人、空字段、非法阶段、记录列数不符均抛 `ValueError`。成功返回按文件记录顺序排列的完整机会数组，每项仅含 `opportunity_id`、`contact_id`、`title`、`stage`，结构与 `add-opportunity` 返回一致。空文件或无表头抛 `ValueError`；只有合法表头（或其后仅有零字段空行）时返回空数组且不写入、不创建数据目录。重新打开同一 root 后可用 `find-opportunities` 查询；`funnel-report` 按归属联系人的当前组织、标签和机会实际阶段统计。导入不改变联系人资料、标签、跟进、提醒及原有机会；旧数据缺少机会集合时按空集合处理，仍可导入。源文件不存在报 `FileNotFoundError`、无读取权限报 `PermissionError`、`csv_path` 非字符串或为空白字符串抛 `ValueError`、缺少该参数抛 `TypeError`。
- `import-contact-tags` → `ContactFlow.import_contact_tags(csv_path)`。面向**已登记联系人**一次性整体批量**追加**标签，不创建联系人、不替换也不清除标签。参数 JSON 形如 `{"csv_path": "contact-tags.csv"}`，相对路径按当前工作目录解释。文件须为 UTF-8（可带 BOM），表头只能是 `contact_id,tag` 两列、名称精确匹配、顺序任意；缺列、重复列或额外列一律拒绝。支持标准 CSV 引号、字段内逗号与换行；只忽略零字段空行，其余记录列数不符、CSV 语法错误或编码非法一律抛 `ValueError`。`contact_id` 去除首尾空白后须非空且区分大小写（`a` 不匹配联系人 `A`）；`tag` 沿用 `set-tags` 的规则：去首尾空白后 casefold、保留内部空白，去首尾空白后为空的标签非法，不能用空标签清除数据。同一联系人可在文件中出现多行，完全相同的记录允许重复；导入标签与该联系人已有标签取去重并集，已有标签一律保留。整份文件共同成功或共同失败：任一记录的联系人未知（即使在后面的行）都整批拒绝，不跳过、不部分写入，失败时原数据文件字节保持不变，数据目录原本不存在时不创建目录或文件。成功返回数组，按规范化标识在文件中首次出现的顺序每人一项，每项仅含 `contact_id` 与 `tags`，`tags` 是导入后该联系人的完整标签集合，按 Unicode 码点升序；重复导入同一文件返回相同结果，全部标签原本已存在时不改写文件。空文件或无表头抛 `ValueError`；合法表头后没有记录（或仅有零字段空行）时返回空数组且不写入、不创建数据目录。重新打开同一 root 后，`get-tags`、`find` 的标签条件与布尔标签表达式，以及各报表的标签筛选都反映新标签；未涉及联系人的标签、联系人资料、跟进、机会及其历史和金额、提醒保持原值，未筛选报表的数量与金额总计不变；旧数据缺少标签集合时按空集合处理，仍可导入。源文件不存在报 `FileNotFoundError`、无读取权限报 `PermissionError`、`csv_path` 非字符串或为空白字符串抛 `ValueError`、缺少该参数抛 `TypeError`。命令成功向标准输出输出 JSON 并退出 0，失败向标准错误输出含 `error` 的 JSON 并退出 2；外层 JSON 数组仍逐项独立调用，后项失败保留先前成功结果。既有 `set-tags` 及其他公开入口行为不变。
- `find` 还接受可选 `tags`（标签数组）和 `tag_mode`（`all` 或 `any`，默认 `all`）：前者要求包含全部标签，后者要求至少匹配一个。省略 `tags` 或传 `None`、空数组时不限制标签；标签条件与组织条件同时满足才返回。
- `find` 另接受可选 `tag_expression`（默认 `None`），用一段布尔表达式同时描述多组标签的包含与排除：标签写作 JSON 双引号字符串（支持 JSON 转义），`&&`、`||`、`!` 分别表示且、或、非，优先级依次为 `!`、`&&`、`||`，圆括号可嵌套，`!` 可连续使用，字符串外的 Unicode 空白忽略；双引号内的运算符和括号属于标签内容。标签解码后沿用 `set-tags` 的去首尾空白与 casefold 规范化，保留内部空白。省略或传 `None` 时行为与之前完全一致；提供时表达式与 `organization`、`tags`、`tag_mode` 条件取交集，原参数的匹配与校验不变。不存在的标签按不包含处理（其否定为真）；旧数据缺少标签集合或联系人没有标签时按空集合计算，所以只含排除条件的合法表达式可以选中无标签联系人。`tag_expression` 非 `None` 时须为非空白字符串；类型非法、标签规范化后为空、非法 JSON 字符串或转义、裸标签、未知符号、缺少操作数、相邻标签没有运算符、空括号、括号不配对或末尾多余内容均抛 `ValueError`，整段表达式在读取数据前完整校验，不因空库、组织无匹配或前段条件已成立而忽略后段错误。结果仍为按联系人标识 Unicode 码点升序的完整联系人数组，每人至多出现一次，无匹配返回空数组；查询只读，成功或失败均不创建目录、不改写数据。`find` 命令的 JSON 对象可携带同名参数，外层数组继续逐项独立查询。
- `duplicate-candidates` → `ContactFlow.duplicate_candidates(organization=None, tags=None, tag_mode="all")`。在合并前查询当前 root 内的重复联系人候选，只读：不创建目录、不改写数据、不另存文件，也不执行任何合并。`organization`、`tags`、`tag_mode` 的默认值与筛选含义同 `find`（先筛选联系人，再在结果内部配对；任一成员不符合筛选条件时整对不返回）。比较时仅对姓名和组织依次做 Unicode NFKC 规范化、casefold 并删除全部 Unicode 空白，存储的原始资料不变。两人的组织比较值相同，且姓名比较值完全相同或只需一次单码点插入、删除或替换即可互转时返回该对（相邻字符交换算两次操作，不匹配；不做传递性补对）。返回数组每项仅含 `left`、`right`、`distance`：前两者是与 `add` 返回结构一致的当前完整联系人对象，`distance` 为姓名所需的最少操作数（0 或 1）。`left` 的联系人标识按 Unicode 码点小于 `right`，每对只出现一次；数组先按 `distance` 升序，再按两侧标识依次升序。无联系人、符合筛选条件的联系人少于两人或没有候选时返回空数组。`organization` 非字符串且非 `None`、标签不合法、`tag_mode` 不是 `all`/`any` 时抛 `ValueError`，空库同样校验；旧数据缺少标签集合时按空集合处理。更新、导入或合并后重新查询按当前资料与标签计算，被合并的源联系人不再出现。
- `search-contacts` → `ContactFlow.search_contacts(query, max_distance=1, organization=None, tags=None, tag_mode="all", limit=20, offset=0)`。在当前 root 的联系人中按姓名片段做容错检索，只读：不创建目录、不改写数据、不另存文件。`query` 必填，是非空字符串；姓名与 `query` 都依次经过 Unicode NFKC 规范化、casefold 并删除全部 Unicode 空白，仅用转换后的值匹配，返回资料仍保留存储原值。每位联系人的 `distance` 是关键词与其姓名任意非空连续片段之间的最小编辑距离，距离按 Unicode 码点计算，插入、删除、替换各计一步，相邻字符交换算两步；距离不超过 `max_distance` 才入选，`0` 表示关键词精确出现在转换后的姓名中。`max_distance` 可选，默认 `1`，只接受整数 `0`、`1`、`2`，布尔值不接受。`organization`、`tags`、`tag_mode` 的默认值与筛选含义同 `find`（标签规则同 `set-tags`），与姓名条件取交集。`limit` 默认 `20`、`offset` 默认 `0`，分别为每页条数与跳过条数；`limit` 必须为正整数，`offset` 必须为非负整数，布尔值不接受。
  - 结果仅含 `total` 和 `matches`：`total` 是分页前的匹配人数；`matches` 每项仅含 `contact`（与 `add` 返回结构一致的当前完整联系人）和整数 `distance`。先按 `distance` 升序、再按联系人标识 Unicode 码点升序，之后再应用分页；每位联系人至多出现一次。无匹配返回 `0` 和空数组；`offset` 达到或超过总数时保留 `total` 并返回空页。
  - `query` 非字符串或转换后为空、`max_distance` 不是 `0`/`1`/`2`、`limit` 非正整数、`offset` 非非负整数、组织类型或标签非法、`tag_mode` 不是 `all`/`any` 时统一抛 `ValueError`，空库同样校验参数；缺少 `query` 抛 `TypeError`。旧数据缺少标签集合时视为空集合。重开同一 root、更新姓名或标签、导入或合并联系人后按当前状态重新查询，被合并的源联系人不再出现。
- `add-opportunity` → `ContactFlow.add_opportunity(opportunity_id, contact_id, title)`。为已存在的联系人新建销售机会，返回仅含 `opportunity_id`、`contact_id`、`title`、`stage` 的对象，初始阶段为 `new`。标识与标题去除首尾空白后须非空；标识区分大小写（`O1` 与 `o1` 不同），标题内部空白保留。一个联系人可有多个机会；机会标识在同一 root 内全局唯一，与联系人标识互不占用，重复标识（即使内容完全相同）一律拒绝。
- `set-stage` → `ContactFlow.set_stage(opportunity_id, stage, on=None)`。返回更新后的完整机会。阶段只能是 `new`（新建）、`qualified`（已确认需求）、`won`（成交）、`lost`（流失）；允许的转移只有 `new→qualified`、`new→lost`、`qualified→won`、`qualified→lost`，其余跨阶段转移一律拒绝。重复设置当前阶段视为成功但不写文件、不追加历史记录；终态（`won`/`lost`）不可再改。可选的 `on` 是变更业务日期：省略或传 `None`（JSON `null`）时记录保存 `null`；提供时须为去除首尾空白后的真实 `YYYY-MM-DD` 字符串（允许过去、未来日期与合法闰日，不读取系统日期），且不得早于该机会最近一条非 `null` 记录日期（同日允许，`null` 记录不影响下限）。每次合法且真正改变阶段时追加一条仅含 `from_stage`、`to_stage`、`on` 的历史记录，阶段修改与记录追加在同一次写入中共同成功；历史不混入机会返回对象。非法日期或日期倒退抛 `ValueError`，且不改变阶段与历史。
- `set-stages` → `ContactFlow.set_stages(updates)`。一次提交多个不同机会的阶段变更，批内所有变更共同成功或共同失败（原子），阶段与转移规则完全沿用 `set-stage`，每个机会都按调用前的当前阶段校验。`updates` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是含 `opportunity_id`、`stage` 与可选 `on` 的对象，不允许其他键：元素不是对象、缺少必填键或含多余键均抛 `ValueError`；`updates` 不是列表同样抛 `ValueError`。机会标识去除首尾空白后须为非空字符串且区分大小写，规范化后的标识在批内重复时整批拒绝——即使两项内容完全相同也不例外。`stage` 去除首尾空白后只接受 `new`、`qualified`、`won`、`lost` 四种既有阶段，不转换大小写；非法阶段、未知机会或非法转移（含从终态再转出）均抛 `ValueError`。`on` 省略或传 `None`（JSON `null`）时，真正变更的历史日期保存为 `null`；提供时规则与 `set-stage` 相同：去除首尾空白后的真实 `YYYY-MM-DD` 字符串，允许过去、未来日期与合法闰日，不读取系统日期，且不得早于该机会（调用前已保存的）最后一条非 `null` 历史日期，同日允许。即使该项重复设置当前阶段也仍校验日期，校验失败整批拒绝；重复设置成功后不追加历史、也不单独写文件。成功返回按输入顺序排列的完整机会数组，结构与 `find-opportunities` 一致：机会标识、归属、标题保持不变，已有金额原样保留，未设置金额时不补金额字段。真正改变阶段的机会各追加一条仅含 `from_stage`、`to_stage`、`on` 的历史，所有阶段修改与历史追加在同一次写入中共同保存；整批均未改变阶段时返回完整数组而不改写文件。任何校验失败都不保留部分变更，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。重新打开同一 root 后，机会查询、阶段历史、`funnel-report` 数量与 `opportunity-amount-report` 金额均反映成功结果，联系人资料、标签、跟进、提醒、机会归属和标题均保留；旧数据缺少机会集合时按空集合处理（非空批次因机会未知抛 `ValueError`），缺少阶段历史集合时从空历史开始追加。命令通过含 `updates` 的 JSON 对象提交一批；外层 JSON 数组仍是对整批方法的逐项独立调用，先前成功的批次保留，后批失败不回滚已成功批次。
- `reopen-opportunities` → `ContactFlow.reopen_opportunities(reopens)`。一次提交整批已关闭机会的重新打开，批内所有重开共同成功或共同失败（原子）。`reopens` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `opportunity_id`、`expected_stage`、`on` 三个键的对象：元素不是对象、缺键或多键均抛 `ValueError`，`reopens` 不是列表同样抛 `ValueError`。机会标识与预期阶段去除首尾空白后须为非空字符串，标识区分大小写，阶段不转换大小写且只接受 `won` 或 `lost`，并须等于该机会调用前的当前阶段；`on` 必填，沿用既有真实日期规则：去除首尾空白后的真实 `YYYY-MM-DD` 字符串，允许过去、未来日期与合法闰日，不读取系统日期，且不得早于该机会最后一条非 `null` 历史日期，同日允许。标识非法、预期阶段非法或不符、日期非法或倒退、未知机会，或规范化后的机会标识在批内重复（即使两项完全相同）均抛 `ValueError`；未重新关闭就再次打开（当前阶段已是 `qualified`）同样抛 `ValueError`，重新关闭后可再次打开。成功将各机会改为 `qualified`，按输入顺序返回完整机会数组，结构与 `find-opportunities` 一致：机会标识、归属、标题保持不变，已有金额原样保留，未设置金额时不补金额字段。每个机会在原历史末尾追加一条仅含 `from_stage`、`to_stage`、`on` 的记录，分别为原关闭阶段、`qualified` 和规范化日期；所有阶段修改与历史追加在同一次写入中共同保存。任何校验失败都不保留部分变更，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。旧数据缺少机会集合时按空集合处理（非空批次因机会未知抛 `ValueError`），缺少阶段历史集合时从当前阶段开始记录，不补推历史。重新打开同一 root 后结果仍有效：`funnel-report` 数量与 `opportunity-amount-report` 金额按 `qualified` 统计且总条数、金额总计不变，`stage-change-report` 显示新记录，`stalled-opportunities` 从本次重开日期计算，`win-cycle-report` 与 `conversion-report` 保留既有口径和旧成交事件；`set-stage`、`set-stages` 仍拒绝从终态直接转出，其他公开入口不变。命令通过含 `reopens` 的 JSON 对象提交一批，成功输出 JSON 并退出 0，失败向标准错误输出含 `error` 的 JSON 并退出 2；外层 JSON 数组仍是对整批方法的逐项独立调用，后项失败保留前项结果。
- `stage-history` → `ContactFlow.stage_history(opportunity_id)`。按成功变更的先后顺序返回该机会的阶段历史数组（不按日期重排），每项仅含 `from_stage`、`to_stage`、`on`；新建、CSV 导入或旧数据中没有实际记录的机会返回空数组，已有阶段仅作为后续记录的起点，不反推历史。只读，不创建目录或改写数据；标识非法或机会未知抛 `ValueError`。金额设置、批量转交和联系人合并不改变历史，归属变化后仍按原机会标识查询。
- `correct-stage-dates` → `ContactFlow.correct_stage_dates(corrections)`。为已有阶段历史记录批量补录或修正业务日期，一次提交整批更正，批内所有更正共同成功或共同失败（原子）。`corrections` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `opportunity_id`、`index`、`on` 三个键的对象：元素不是对象、缺键或多键均抛 `ValueError`，`corrections` 不是列表同样抛 `ValueError`。机会标识去除首尾空白后须为非空字符串且区分大小写；`index` 只接受非负整数（布尔值不接受），对应调用前该机会 `stage-history` 数组中从零开始的位置，位置越界抛 `ValueError`；`on` 沿用既有真实日期规则：去除首尾空白后的真实 `YYYY-MM-DD` 字符串，允许过去、未来日期与合法闰日，拒绝 `null`，不读取系统日期。机会未知或该机会旧数据缺少历史（按空数组处理）时任何 `index` 都越界。规范化后同一机会的同一位置在批内重复（即使两项完全相同）整批拒绝；同一机会可更正多条记录，多个机会也可在同一批共同提交。整批按更正后的最终历史判断：涉及机会的非 `null` 日期按保存顺序不得倒退，同日允许，未更正的 `null` 不参与比较；最终若有倒退抛 `ValueError`，同时调整多条日期时只要最终顺序合法即成功。成功按输入顺序返回更正后的历史记录数组，每项结构与 `stage-history` 一致（仅含 `from_stage`、`to_stage`、`on`）。全部日期规范化后均未变化时返回对应记录而不改写文件；任何校验失败都保留原数据文件字节，原本不存在的数据目录和文件不被创建。更正只改历史记录的 `on`：机会当前阶段、归属、标题、金额、历史阶段字段（`from_stage`、`to_stage`）与记录顺序保留，联系人、标签、跟进和提醒不变。重新打开同一 root 后，阶段历史查询、相关日期报表（`stage-change-report`、`win-cycle-report`、`conversion-report`）与滞留机会查询（`stalled-opportunities`）按更正后的日期和既有口径重算；既有公开入口及报表的筛选、分组和 CSV 格式保持原义。命令通过含 `corrections` 的 JSON 对象提交一批，成功向标准输出返回 JSON 并退出 0，失败向标准错误返回含 `error` 的 JSON 并退出 2；外层 JSON 数组仍是对整批方法的逐项独立调用，先前成功的批次保留，后批失败不回滚已成功批次。
- `find-opportunities` → `ContactFlow.find_opportunities(contact_id=None, stage=None)`。按可选联系人和阶段筛选，省略或传 `None` 时不限制该条件，两个条件取交集；返回按机会标识 Unicode 码点升序排列的对象数组，无匹配返回空数组。显式指定不存在的联系人报 `ValueError`（省略不校验）。旧数据没有机会时视为空集合，查询及被拒绝的操作都不会创建目录或文件。
- `transfer-opportunities` → `ContactFlow.transfer_opportunities(transfers)`。独立的批量机会归属调整，与联系人合并无关：源联系人与目标联系人都保留，不移动联系人资料、标签、跟进记录或提醒。一次提交整批转交，批内所有调整共同成功或共同失败（原子）。`transfers` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `opportunity_id`、`source_contact_id`、`target_contact_id` 三个键的对象：三个标识去除首尾空白后均须为非空字符串且区分大小写，元素不是对象、缺键或多键、标识非法均抛 `ValueError`；`transfers` 不是列表同样抛 `ValueError`。三个标识中源联系人和目标联系人都须存在，机会须存在，且源联系人必须与该机会当前实际归属一致；联系人未知、机会未知或来源不符均抛 `ValueError`，空库同样校验。规范化后的机会标识在批内重复时整批拒绝——即使两项内容完全相同，或在批内连续转交同一机会，也不例外。成功返回按输入顺序排列的完整机会数组，结构与 `find-opportunities` 一致，只改变归属：`contact_id` 变为目标联系人，机会标识、标题、阶段和金额保持原值，未设置金额时不补金额字段。来源与目标相同且核对通过时该项返回原机会；整批均未改变归属时不改写文件。任何校验失败都不保留部分调整，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。四种既有阶段（含 `won`/`lost` 终态）的机会均可调整，转交不做也不改变阶段；同一批可把多个不同机会移交同一联系人。重新打开同一 root 后，`find-opportunities` 按新归属查询，`funnel-report` 和 `opportunity-amount-report` 按目标联系人的当前组织及标签重新分组和筛选，未筛选时联系人总数、机会总数、各阶段数量及金额总计不变。旧数据缺少机会集合时按空集合处理（任何机会都未知，整批拒绝），缺少其他可选集合不妨碍操作。命令通过含 `transfers` 的 JSON 对象提交一批；外层 JSON 数组仍是对整批方法的逐项独立调用，先前成功的批次保留。
- `funnel-report` → `ContactFlow.funnel_report(organization=None, tags=None, tag_mode="all")`。按组织生成销售漏斗统计，返回仅含 `total`、`organizations`、`csv` 的对象，只读不创建目录或改写数据。`organization`、`tags`、`tag_mode` 的筛选含义与 `find` 一致（标签规则同 `set-tags`，组织与标签条件取交集）。统计只反映机会当前阶段：`won`/`lost` 不反推为 `qualified`，没有机会的联系人只计联系人数、不计 `new`，同一联系人的多个机会逐条计数。
  - `total` 含 `contacts`、`new`、`qualified`、`won`、`lost`、`opportunities` 六个整数，依次为筛选后联系人总数、四个阶段的机会条数和机会总数。
  - `organizations` 是按组织归组的统计数组，每项比 `total` 多一个 `organization` 字段，并包含有联系人但无机会的组织。组织按 `casefold` 值归组，同组显示名取筛选后组织原值中 Unicode 码点最小者，数组按归组值升序。无匹配时 `total` 全零且数组为空；旧数据没有机会时各阶段计数为零。
  - `csv` 是字符串，表头固定为 `organization,contacts,new,qualified,won,lost,opportunities`，只输出组织行，顺序与数值与 `organizations` 一致；没有组织时只有表头。字段按标准 CSV 规则转义并保留字段内换行，记录用 LF 分隔且末尾有换行。
  - 合并联系人后，其机会按目标联系人的当前组织和标签重新归组，全局机会总数不因合并增加。`organization` 非字符串且非 `None`、标签不合法、`tag_mode` 不是 `all`/`any` 时抛 `ValueError`。
- `set-opportunity-amount` → `ContactFlow.set_opportunity_amount(opportunity_id, amount)`。为已存在的机会设置人民币元金额，终态（`won`/`lost`）也可设置，返回仅含 `opportunity_id` 与 `amount` 的对象。标识规则同 `set-stage`（去首尾空白后非空、区分大小写）。`amount` 只接受字符串：去首尾空白后是仅含 ASCII 数字与至多一个小数点的非负十进制数，整数部分至少一位，小数部分若出现为一至两位；允许零与前导零，不接受符号、指数、千分位分隔符及数值类型。返回与保存的金额去掉多余前导零并固定两位小数（如 `007.5` 归一为 `7.50`）。非法标识、未知机会或非法金额抛 `ValueError`，缺少必填参数抛 `TypeError`；任何失败都不改写原文件、不创建原本不存在的目录。金额与当前值相同（含未设置金额时设零）返回成功且不改写文件；金额保存至本地数据，重开同一 root 后仍有效。
- `set-close-dates` → `ContactFlow.set_close_dates(updates)`。一次提交整批机会预期成交日期的维护，批内所有更新共同成功或共同失败（原子）。`updates` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `opportunity_id` 与 `expected_close_on` 两个键的对象：元素不是对象、缺键或多键均抛 `ValueError`，`updates` 不是列表同样抛 `ValueError`。机会标识去除首尾空白后须为非空字符串且区分大小写（`O1` 与 `o1` 不同），规范化后的标识在批内重复时整批拒绝——即使两项内容完全相同也不例外。`expected_close_on` 传 `None`（JSON `null`）表示清除该机会的日期字段；提供时须为去除首尾空白后的真实 `YYYY-MM-DD` 字符串，允许过去、未来日期与合法闰日（如 `2024-02-29`），不读取系统日期；非字符串、空白或非法日历值均抛 `ValueError`。机会未知抛 `ValueError`，空库同样校验。终态（`won`/`lost`）机会也能维护日期。成功按输入顺序返回完整机会数组，结构与 `find-opportunities` 一致：设置后对象携带 `expected_close_on` 字段，清除后该字段消失，机会标识、归属、标题、阶段及金额等其他字段保留，未设置金额时不补金额字段。整批规范化后的日期（设置或清除）均与现状相同时返回完整数组而不改写文件。任何校验失败都不保留部分修改，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。转交、合并、联系人更名及阶段变更（含重开）都保留该日期；新建机会和 CSV 导入不自动添加日期。成功修改后重新打开同一 root，`find-opportunities` 仍显示维护后的日期字段，其他资料与关联数据保留；旧数据缺少机会集合时按空集合处理（非空批次因机会未知抛 `ValueError`），其余公开入口不变。命令通过含 `updates` 的 JSON 对象提交一批，成功向标准输出输出 JSON 并退出 0，失败向标准错误输出含 `error` 的 JSON 并退出 2；外层 JSON 数组仍是对整批方法的逐项独立调用，先前成功的批次保留，后批失败不回滚已成功批次。
- `opportunity-amount-report` → `ContactFlow.opportunity_amount_report(organization=None, tags=None, tag_mode="all")`。按组织汇总机会金额，返回仅含 `total`、`organizations`、`csv` 的对象，只读不创建目录或改写数据。参数名、默认值及筛选语义与 `funnel-report` 完全一致，非法值抛 `ValueError`，空库同样先校验。`total` 含 `new`、`qualified`、`won`、`lost`、`amount` 五个两位小数字符串：前四项按机会当前阶段逐条累计金额，`amount` 为四者之和，累加以分为单位精确计算；未设置金额的机会按 `0.00` 计入。`organizations` 每项比 `total` 多一个 `organization` 字段，分组、显示名与顺序同数量漏斗，保留有联系人但无机会的零金额组织。`csv` 表头固定为 `organization,new,qualified,won,lost,amount`，数据行与分组一致，字段按标准 CSV 规则转义并保留字段内换行，记录用 LF 分隔且末尾有换行；无匹配时 `total` 全零、分组为空、`csv` 仅含表头。阶段切换后金额归入新阶段，更新联系人资料或标签后按当前归属分组筛选，合并联系人保留金额且不重复累计；旧数据缺少机会或标签集合时按空集合处理。
- `forecast-report` → `ContactFlow.forecast_report(probabilities, organization=None, tags=None, tag_mode="all", start_on=None, end_on=None)`。按阶段成交概率计算未结机会的预测金额，返回仅含 `total`、`organizations`、`csv` 的对象，只读不创建目录、不改写数据或另存文件。`probabilities` 必填，缺少抛 `TypeError`；它必须是恰含 `new` 与 `qualified` 两个键的对象，两个值是百分比字符串，语法同金额（去首尾空白后的非负十进制数，至多两位小数），范围为 0 至 100 且包含端点；概率不保存，仅用于本次查询。`organization`、`tags`、`tag_mode` 的默认值、规范化与筛选语义与 `funnel-report` 完全一致；概率结构、概率值或筛选参数非法均抛 `ValueError`，空库同样先校验。`start_on`、`end_on` 为可选的预期成交日期区间：两者同时省略或均为 `null` 时完全保留原行为（统计全部当前 `new`/`qualified` 机会）；否则两者必须同时提供，各自为去除首尾空白后的真实 `YYYY-MM-DD` 字符串（允许过去、未来日期与合法闰日，不读取系统日期），范围包含两端，起始日晚于结束日抛 `ValueError`。只给一边、日期非法或起始晚于结束均抛 `ValueError`，空库同样先校验。提供区间时只统计自身带有 `expected_close_on`（由 `set-close-dates` 维护）且日期落在区间内、当前阶段为 `new` 或 `qualified` 的机会；没有日期的机会和 `won`、`lost` 终态机会一律排除，绝不借用阶段历史中的日期替代。无日期区间时只按当前阶段判断（原行为）。每个入选机会计一次，未设置金额按 `0.00` 计算。每条按金额乘概率除以 100 的精确结果累计，各阶段、各组织与总计分别对各自的未舍入累计值半数进位舍入到分，不从已舍入子项反推。`total` 仅含 `new`、`qualified`、`amount` 三个人民币元两位小数字符串，分别为两阶段预测金额及其合计；`organizations` 金额结构同 `total`，另含 `organization`，组织按符合原筛选的联系人分组，分组、显示名与排序同 `funnel-report`，区间内没有入选机会的组织仍保留零金额行；无匹配时 `total` 全为 `0.00`、组织数组为空、`csv` 只有表头。`csv` 表头固定为 `organization,new,qualified,amount`，数据行与分组一致，字段按标准 CSV 规则转义并保留字段内换行，记录用 LF 分隔且末尾有换行。资料、标签、金额、阶段、归属或预期成交日期变化后按当前数据重算；旧数据缺少机会或标签集合时按空集合处理。原有位置参数调用（仅给 `probabilities` 及组织、标签参数）保持兼容。命令沿用 JSON 输入、外层数组逐项调用及成功退出 0、错误 JSON 退出 2 的规则。
- `monthly-forecast-report` → `ContactFlow.monthly_forecast_report(probabilities, start_on, end_on, organization=None, tags=None, tag_mode="all")`。按自然月查看未结机会的预测金额，返回仅含 `total`、`months`、`csv` 的对象，只读不创建目录、不改写数据或另存文件。`probabilities`、`start_on`、`end_on` 均必填，缺少抛 `TypeError`；`probabilities` 的结构、概率语法与范围规则同 `forecast-report`，`start_on`、`end_on` 各自为去除首尾空白后的真实 `YYYY-MM-DD` 字符串（允许过去、未来日期与合法闰日，不读取系统日期），范围包含两端并支持跨年；概率、日期或筛选参数非法、日期为 `null` 或起始晚于结束均抛 `ValueError`，空库同样先校验。`organization`、`tags`、`tag_mode` 的默认值、规范化与筛选语义与 `forecast-report` 完全一致。查询只纳入当前 `new` 或 `qualified` 且自身 `expected_close_on` 落在区间内的机会，每条按当前归属联系人的组织和标签筛选，再按预计成交月份归组；没有预计日期的机会和 `won`、`lost` 终态机会一律排除，绝不借用阶段历史中的日期替代，未设置金额按 `0.00` 计算。`months` 按升序覆盖区间涉及的每个自然月（含没有入选机会的月份），每项仅含 `month`（`YYYY-MM`）、`new`、`qualified`、`amount`，首尾月份仅统计区间内日期，空月各金额为 `0.00`。每条按金额乘概率除以 100 的精确结果累计，各阶段、各月合计与总计分别对各自的未舍入累计值半数进位舍入到分，返回两位小数字符串，不从已舍入的月值反推总计；同一条件下 `total` 与 `forecast-report` 的区间预测结果一致。空库或筛选无匹配也返回完整月份的零金额行和全零 `total`。`csv` 表头固定为 `month,new,qualified,amount`，数据行与 `months` 完全一致，字段按标准 CSV 规则转义，记录用 LF 分隔且末尾有换行，不另写导出文件。旧数据缺少机会或标签集合时按空集合处理。命令沿用 JSON 对象输入、外层数组逐项调用、成功输出 JSON 并退出 0、错误 JSON 退出 2 的规则。
- `followup-report` → `ContactFlow.followup_report(start_on, end_on, organization=None, tags=None, tag_mode="all")`。跨联系人查询指定日期范围内的跟进记录，返回仅含 `records` 和 `csv` 的对象，只读不创建目录或改写数据，也不写出导出文件。`start_on`、`end_on` 规则同 `due_on`（去除首尾空白的 `YYYY-MM-DD` 真实日期，允许合法闰日），范围包含两端，起始日晚于结束日抛 `ValueError`。`organization`、`tags`、`tag_mode` 的筛选含义与 `find` 一致（组织与标签条件取交集；省略组织或传 `None` 不限制组织，省略标签、传 `None` 或空数组不限制标签）。没有跟进记录的联系人不产生结果，机会阶段和提醒不影响查询。
  - `records` 是数组，每项只含 `contact_id`、`name`、`email`、`organization`、`on`、`note`；资料取联系人的当前值，日期和备注保留原内容。先按日期升序，再按联系人标识的 Unicode 码点升序，同日同一联系人按保存顺序排列，重复记录逐条保留。更新或合并联系人后，记录按当前联系人资料及标签筛选和展示。

  - 日期或天数非法、组织非字符串且非 `None`、标签非法、`tag_mode` 不是 `all`/`any` 时抛 `ValueError`，空库同样校验参数；缺少必填参数抛 `TypeError`。旧数据缺少跟进或标签集合时按空集合处理；重新打开 root、更新资料、导入跟进或合并联系人后按当前资料、标签和记录归属重新计算。
- `stalled-opportunities` → `ContactFlow.stalled_opportunities(as_of, stalled_days, organization=None, tags=None, tag_mode="all")`。按指定截止日查询当前阶段为 `qualified`（已确认需求）的滞留机会，只读不创建目录或改写数据，也不另存名单。`as_of` 规则同 `inactive-contacts` 的截止日（去除首尾空白后的真实 `YYYY-MM-DD` 字符串，允许合法闰日、过去与未来日期，不读取系统日期）；`stalled_days` 必须为正整数，布尔值不接受。`organization`、`tags`、`tag_mode` 的默认值、规范化与筛选含义同 `funnel-report`（组织与标签条件取交集，按机会当前归属联系人的资料和标签判断）。不重建截止日的历史阶段：只判断当前阶段为 `qualified` 的机会，跟进、提醒和金额不影响入选，未设置金额时不补金额字段。
  - 起点取每个机会按保存顺序最后一条 `to_stage` 为 `qualified` 的历史记录（通常是 `new→qualified` 那条，重入等旧历史也按保存顺序最后一条计）。其 `on` 非 `null` 且不晚于 `as_of` 时，按真实日历计算 `as_of` 与起点之间的自然日差（跨月、跨年、闰日按真实日历，同日为零天），达到 `stalled_days` 即入选，恰好达到阈值也包含；起点晚于截止日则排除。没有这类历史（如直接以 `qualified` 导入的机会、旧数据）或该条历史的 `on` 为 `null` 时也入选，`entered_on` 和 `age_days` 均为 `null`，不借用其他日期补齐。转出 `qualified`（进入 `won`/`lost`）后排除。
  - 返回数组，每项仅含 `opportunity`、`contact`、`entered_on`、`age_days`：前两者分别为与 `find-opportunities` 和 `add` 返回结构一致的当前完整机会与联系人，后两者为起点日期和上述日差（未知起点时均为 `null`）。未知起点者先按机会标识 Unicode 码点升序，其余按天数降序、机会标识升序；每个机会只出现一次，同一联系人的多个机会分别判断，无匹配返回空数组。
  - 日期或天数非法、组织非字符串且非 `None`、标签或匹配模式非法时均抛 `ValueError`，空库同样校验参数；缺少必填参数抛 `TypeError`。旧数据缺少机会、阶段历史或标签集合时按空集合处理；重开 root、更新资料或标签、转交机会或合并联系人后按当前归属重算。命令通过含 `as_of`、`stalled_days` 及可选筛选参数的 JSON 对象调用，外层 JSON 数组逐项独立调用；成功向标准输出返回 JSON 并退出 0，失败向标准错误返回错误 JSON 并退出 2。
- `set-reminder` → `ContactFlow.set_reminder(contact_id, due_on, note)`。为已存在的联系人设置下一次跟进提醒。每位联系人至多保留一条提醒，再次设置整条替换；返回仅含 `contact_id`、`due_on`、`note` 的对象。`contact_id` 与 `note` 去除首尾空白后须非空，标识区分大小写，备注内部空白保留。`due_on` 只接受去除首尾空白后的 `YYYY-MM-DD` 且日期真实有效（允许过去日期与合法闰日，如 `2024-02-29`）；参数非字符串、去空白后为空或日期非法均抛 `ValueError`。未知联系人抛 `ValueError` 且不写文件。
- `clear-reminder` → `ContactFlow.clear_reminder(contact_id)`。清除联系人的提醒：有提醒则删除并返回 `true`；本就没有提醒时返回 `false` 且不写文件。标识非法或联系人未知抛 `ValueError`。
- `complete-reminder` → `ContactFlow.complete_reminder(contact_id, on, note, next_reminder=None)`。完成联系人当前提醒：一次操作追加一条跟进记录并处理下一次提醒，两者共同成功或共同失败。返回仅含 `followup` 与 `reminder` 的对象，前者结构与 `follow-up` 的记录一致，后者与 `set-reminder` 的提醒结构一致，没有后续提醒时为 `null`。`contact_id`、`on`、`note` 的校验分别同 `set-reminder` 的标识、`due_on` 的日期规则与备注规则（`on` 允许早于或晚于原到期日，不读取系统日期）。省略 `next_reminder` 或传 `null` 时清除原提醒；提供时它必须是恰含 `due_on` 与 `note` 的对象，字段校验同 `set-reminder`，且新到期日须严格晚于 `on`。参数非法、未知联系人、没有当前提醒、`next_reminder` 缺项或含额外键、新到期日不晚于完成日期均抛 `ValueError`，且不追加跟进、不清除或替换提醒、不改写数据文件；旧数据缺少提醒集合时视为没有提醒。
- `complete-reminders` → `ContactFlow.complete_reminders(completions)`。在单条完成基础上的整批完成：一次提交多条完成，批内所有项目共同成功或共同失败（原子），逐项沿用 `complete-reminder` 的语义——先追加一条跟进记录，再清除或替换该联系人的提醒，所有跟进追加与提醒处理在同一次写入中共同保存。`completions` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是含 `contact_id`、`expected_due_on`、`on`、`note` 与可选 `next_reminder` 的对象，不允许其他键：`completions` 不是列表、元素不是对象、缺键或多键均抛 `ValueError`。`contact_id` 去除首尾空白后须为非空字符串且区分大小写，规范化后的标识在批内重复时整批拒绝——即使两项内容完全相同也不例外。`on`、`expected_due_on` 与（提供时）`next_reminder.due_on` 均沿用既有真实 `YYYY-MM-DD` 日期校验（去除首尾空白、允许过去与未来日期及合法闰日，不读取系统日期）；完成日 `on` 可早于或晚于原到期日，新到期日严格晚于完成日。备注去除首尾空白后须非空，保留内部空白与换行。`next_reminder` 省略或为 `null` 时清除提醒，否则必须是仅含 `due_on`、`note` 的对象，校验规则与单条完全一致。执行时核对 `expected_due_on` 与该联系人**当前**提醒的到期日：完全相同才处理，备注不参与核对；未知联系人、没有当前提醒或到期日不符均抛 `ValueError`。成功返回按输入顺序排列的数组，每项仅含 `followup` 和 `reminder`，结构与单条结果完全一致，无后续提醒时 `reminder` 为 `null`。任何校验失败都不追加任何跟进、不清除或替换任何提醒，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。重新打开同一 root 后，跟进查询（`timeline`、`followup-report`）与到期提醒查询（`due-reminders`）反映成功结果：同日同一联系人的旧跟进排在本批新记录之前；批内联系人互不相同，提醒按联系人各处理一条。联系人资料、标签、机会及其历史和金额均保留；旧数据缺少跟进集合时可从空集合追加，缺少提醒集合时非空批次因没有当前提醒而拒绝。命令通过含 `completions` 的 JSON 对象提交一批；外层 JSON 数组仍是对整批方法的逐项独立调用，先前成功的批次保留，后批失败不回滚已成功批次。
- `postpone-reminders` → `ContactFlow.postpone_reminders(updates)`。仅批量调整待办到期日：不追加跟进记录，也不清除或重建提醒。一次提交整批延期，批内所有项目共同成功或共同失败（原子）。`updates` 只接受列表，空列表返回空数组且不写入、不创建数据目录；缺少该参数抛 `TypeError`（经标准错误信封返回 2）。每项是恰含 `contact_id`、`expected_due_on`、`due_on` 三个键的对象：元素不是对象、缺键或多键均抛 `ValueError`，`updates` 不是列表同样抛 `ValueError`。`contact_id` 去除首尾空白后须为非空字符串且区分大小写（`a` 不匹配联系人 `A`）；`expected_due_on` 与新 `due_on` 都沿用既有真实日期规则：去除首尾空白后的真实 `YYYY-MM-DD` 字符串，允许过去日期、跨年与合法闰日（如 `2024-02-29`），不读取系统日期；字段类型或值非法均抛 `ValueError`。执行时按**调用前**状态逐项核对：联系人未知、没有当前提醒（旧数据缺少提醒集合时按没有提醒处理）、当前到期日与 `expected_due_on` 不符，或新 `due_on` 早于 `expected_due_on`（同日允许）均抛 `ValueError`；规范化后的联系人标识在批内重复时整批拒绝——即使两项内容完全相同也不例外。延期只改变提醒的 `due_on`：提醒备注原样保留，已有 `repeat_monthly`、`anchor_day` 字段原样保留，一次性提醒不补周期字段；联系人资料、标签、跟进、机会与阶段历史也全部保留。成功按输入顺序返回更新后的完整提醒数组，结构与 `due-reminders` 中的提醒一致；新日期与当前相同的项目返回原提醒，整批均未变化时返回完整数组而不改写文件。周期提醒延期后，随后完成时沿用既有续期规则：以延期后的到期月份为当期，从原锚日（短月钳制到月末）续期，备注与周期字段不变。任何校验失败都不保留部分修改，原数据文件字节保持不变，原本不存在的数据目录和文件不被创建。重新打开同一 root 后，`due-reminders` 按新日期判断到期并保持既有排序（到期日升序、同日按联系人标识 Unicode 码点升序）；设置、清除、完成提醒及其他公开入口的原行为不变。命令通过含 `updates` 的 JSON 对象提交一批，成功输出 JSON 并退出 0，失败向标准错误输出含 `error` 的 JSON 并退出 2；外层 JSON 数组仍是对整批方法的逐项独立调用，后批失败保留前批成功结果。
- `due-reminders` → `ContactFlow.due_reminders(as_of)`。须显式提供截止日期 `as_of`（规则同 `due_on`，不使用系统日期），返回 `due_on` 不晚于 `as_of` 的提醒数组（含当天及逾期项）。结果先按到期日升序，同日再按联系人标识的 Unicode 码点升序；无匹配返回空数组。只读，不创建目录或文件，也不改写数据；旧数据没有提醒时视为空集合。

合并联系人（`merge`）时，源联系人的全部机会（包括 `won`/`lost` 终态机会）同步归入目标联系人，机会标识、标题和阶段保持原值；返回结构与跟进计数不变。提醒也一并归入目标：只有一方有提醒时保留该条；双方都有时取到期日较早者，到期日相同则保留目标原提醒。被保留的提醒沿用所选到期日和备注，仅把 `contact_id` 改为目标标识；源提醒不再出现。记录跟进（`follow-up`）不会自动清除提醒。


命令成功向标准输出打印 JSON 并返回 0；输入或本地文件错误向标准错误输出说明并返回 2。无参数的方法可省略输入文件。数据保存在 `root/data.json`，每次成功修改后保存；适用于单进程本地使用。

## 当前边界

姓名容错检索仅限姓名片段与码点编辑距离（至多 2），不支持跨字段或拼音/语音匹配；下一次跟进提醒仅保留每位联系人的一条，不做重复或周期提醒；邮箱只做基础格式检查，不验证其真实存在。 不承诺并发写入或断电恢复。
